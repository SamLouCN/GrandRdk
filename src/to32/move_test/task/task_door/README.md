# 穿门任务

入口 `t_door.DoorTask`，导出 `DOOR_TABLE=[DoorTask]`。阶段名为 `PassGate`，
沿用 `config/stage_model.py` 的门模型选择。已加入正式 `STAGE_TABLE`，位于
Task2 后、PickBall 前。当前测试开关仍为 True、测试表仍为 Task2+Return；
单独运行门任务时，在 `test_mode/test_config.py` 设置 `TEST_TABLE = DOOR_TABLE`。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `config.py` | 门任务所有标定值、控制增益、容差、推力、阈值及超时 |
| `perception.py` | 畸变/折射校正、YOLO 选门并保持目标、ROI 内 CV 四边、交点和 PnP |
| `front_pipeline.py` | 前视多个 worker 共用一个门跟踪器，同帧 JSON 发布 |
| `overlay.py` | 共享 JPEG 的 YOLO/CV 标注和左下角紧凑姿态数据面板 |
| `observation.py` | 读取观测，区分新帧、重复帧、无门、过期及错误；重置目标握手 |
| `t_door.py` | 非阻塞任务状态机，返回 Mission 控制字典 |
| `test_door.py` | 无相机、无串口的合成几何和状态机测试 |

任务不直接读取 JPEG、不加载 YOLO、不写串口。CV 放在前视进程，避免拖慢
20 Hz 控制循环。`mission.Stage` 继续兼容旧任务，其实现移入无配置依赖的
`stage_base.py`，避免任务注册循环导入。

## 视觉输入和观测契约

与 `quad_cv_kit/demo/demo_video_cv_after.py` 一致：干净 BGR -> 相机校正 ->
YOLO；同一校正图加对比度 1.2、普通锐化 0.6 后交给 CV。
CLAHE 和额外饱和度增强关闭。颜色证据同时参考干净校正图。
YOLO 框贴边时允许 CV ROI 超出框，但不能超出有效图像区域。

前视 `momo_det_front.json` 的 `door` 字段提供目标框、面积占比、四点、
真实红边、浅绿色延长段、PnP 姿态、机器人坐标下的中心及法线。
`capture_ts` 为采集时间，`frame` 为原始采集帧号；这些数据在同一次处理
中生成，不用共享 JPEG 的写序号匹配。识别使用干净校正图；共享 JPEG 在副本上叠加
黄色 YOLO 框、绿色实测边、浅绿色延长线及红色交点，沿用 `/cam1` 回传上位机。
左下角小面板显示屏占比、CV 状态、航向误差（非绝对航向）、不可控倾斜、重投影误差、
门中心与法线对齐位移（米，机器人 X右/Y下/Z前）；无有效姿态时显示不可用原因。
默认字号0.42、行距18px，四行面板通常约占1280×720画面的2%～4%，不铺满整条画面。
显示参数 `overlay_font_scale / overlay_line_height_px / overlay_background_alpha` 在
`config.py` 调整。姿态 JSON 和返回的干净图像不受绘制影响。

面积计算严格为 `(x2-x1)*(y2-y1)/(1280*720)`，输入尺寸不一致拒绝控制。
选门先按面积，其后用 IoU 和尺度保持同一目标，不按最高置信度频繁换门。
只有当前四条实测边支持的交点才有效，允许算法库限制内的端部延长交点；
不从三条边补造第四条边，不以旧跟踪四点通过盲冲判据。

门尺寸固定 0.70×0.50 m，因此 PnP 平移量按米解释；估计精度仍依赖内参、
折射近似及四点质量。尺寸应对应所选管中心线交点间矩形，而非外沿尺寸。
相机坐标为 X右/Y下/Z前，配置的旋转矩阵和安装偏移换算到同约定的机器人坐标。
航向指令采用任务系右转为正，固件镜像只由 mode_auv/test_runner 施加一次。

## 流程

1. 捕获门；仅调整航向和深度，使滤波框中心稳定落在 8 px 容差内。
2. 前进接近并小步纠偏；明显偏离时先停推重新对准。面积 >=50% 后停止接近。
3. 四交点有效时按航向 -> 深度 -> 横移顺序小步回正，每步到位后等待稳定的新帧。
4. 无四点时固定航向和深度，左移小步；比较多个帧的红边支持数量，框宽变化辅助。
   支持变差或框明显变窄时反向；支持改善或框变宽时沿原方向继续。
   横移有累计距离、次数和时间上限，失败后零水平推力保持并报告。
5. 回正后向前接近80%，持续用 CV 纠偏；四点失效时停止接近。
6. 面积 >=80% 后再次验证 CV 法线和中心持续达标，锁定航向、深度。
7. 不再消费视觉，按标定速度定时执行80 cm盲冲。外层急停和模式退出仍生效。
8. 重置目标，等待视觉端确认重置后重新捕获下一门。
9. 连续有效无门帧确认后，在搜索基准航向的 -45°、+45° 到位观察。
   任一位置发现门则重新对准；两侧均无门则返回基准航向。
10. 直行 `exit_distance_m`（暂为0.50 m，可标定修改），然后返回 None 交接后续赛段。

重复帧不重复计数。视觉故障不当成无门，也不当成赛段结束；盲冲前观测失效
主动输出零 surge/sway，不能用 `paused` 留下上一帧前进推力。
`HOLD_FAULT` 为零水平推力、保留目标深度和航向的保持状态，可通过退出并重新进入任务重置。

## 标定入口

修改 `config.py` 的 `DoorConfig` 默认值，无需修改状态机。重点实测：

- 前视校正内参文件及 `camera_fit`、安装旋转 `camera_to_robot_rotation` 和位置 `camera_position_robot_m`。
- 各推力下 `blind_speed_mps / exit_speed_mps / sway_speed_mps`，以及起步时间 `blind_extra_s`。
- 深度运行范围、初始深度、航向/深度/横移符号、步长、稳定时间及容差。
- 80 cm是否覆盖相机到门的剩余距离和尾部通过距离；无门后的交接前进距离。

速度默认值是占位估计：80 cm按0.25 m/s换算为3.2 s，尚非位移闭环。
门尺寸和面积阈值按用户要求保留。70:50门在16:9画面正对且完全可见时，
框面积可能达不到80%；若未同时满足面积和四点质量，会到时保持，不擅自降低阈值。
俯仰/横滚超出配置可控范围时不执行盲冲，因为现有输出壳 pitch/roll固定0。

部署须包含工程根的 `quad_cv_kit/src` 和内参文件；推理复用当前赛段的板端 HBM，
不在控制进程加载桌面 best.pt。要使用与新 best.pt 相同的模型，需准备对应 HBM
并配置 `config/stage_model.py` 的 gate 模型路径和类别。
