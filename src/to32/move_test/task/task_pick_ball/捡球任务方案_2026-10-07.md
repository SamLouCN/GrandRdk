### 0.3 决策记录（为什么是现在这个设计）

| # | 决策 | 理由 |
|---|---|---|
| 1 | **对准 = 纯平移闭环：dx→sway、dy→surge，全程锁 yaw 不转** | 下视相机垂直向下看，转 yaw 只是让机体绕自身竖轴自转，球像绕光心打转，**闭不了「球心→画面中心」这个环**；唯一能改变球像位置的是机体平面平移。与撞球（前视、闭 yaw）是两种完全不同的分配 |
| 2 | KF 用 **x/y 双轴独立 1D CV**（_PickKF2 = 两个 _PickKF），不做 2×2 矩阵 | 平移闭环里两轴解耦（sway 只管 dx、surge 只管 dy），独立滤波等价且免 numpy、免矩阵手写；设计完全继承撞球方案已定稿的 1D _BallKF |
| 3 | PID 的 D 项用 **KF 速度状态 vcx/vcy**，不数值差分 | 过门方案明确约定：自己差分放大噪声，滤波器速度现成 |
| 4 | 坐底目标「5cm」= **离底高度口径**（本工程全部 `AUV_*_DEPTH_CM` 键统一口径），换算 depth_cm = 130−5−20 = **105，在钳位带 [25,110] 内，无冲突** | 澄清（上一轮曾误记"5cm 会被防露头钳位顶住"——那是把 5cm 误读成水深读数；`_depth_out → clamp_depth_cm(target_depth_cm(h))` 全链已核）。想要真压底可设 0（110 恰为钳位上限，仍合法） |
| 5 | 对准完成计数用 **KF 滤波后的 dx/dy** 判窗 | 用户要的"稳定对准"正是滤波含义；raw 抖动会让"连续 10 帧"反复清零难凑齐。推力与计数同源，无两套口径 |
| 6 | 对准超时兜底 = **置 `ctx.pick_lost=True` + 跳到上浮子步骤**（不上浮到离面） | 车在对准段始终在 60cm 离底（安全），超时直接回上浮段收尾、状态出口统一；与撞球方案 ball_lost 同一 setattr 机制，下游 Drop 等阶段 enter 秒退即可跳过 |
| 7 | 坐底保持 1s（hover_step）是**未来合爪动作的挂点** | V2 协议 0x09 无 claw 位（通道缺口），现阶段 1s 纯定时保持 + 固件深度环持续下压；通道打通后在这一拍发合爪 |
| 8 | 前冲 0.5s 定时开环（不做视觉终止判据） | 爪偏置补偿量只与机体几何/推力有关，固定时长最简可标定；"球出画/框宽突增即停"留作扩展位（见 §0.4-2） |

### 0.4 待拍板问题（落地前用户确认；未确认时按"默认"实现）

1. 前冲 0.5s 的 surge 档：默认不显式给（forward_step 默认巡航推力）；要改再加 `AUV_PICK_FWD_SURGE`。
2. 前冲要不要加辅助终止（球出画/框宽占比突增 → 提前停）：默认**不加**（纯定时 0.5s），上车标定后若抓偏再加。
3. 对准失败兜底：默认置 pick_lost + 跳上浮（车在 60cm 离底已安全）；备选"再上浮到离面安全"更保守——默认不采用。
4. 坐底高度 5cm 的物理含义：默认按统一公式（爪尖离底 5cm，20cm 机体偏置口径）；若实车要爪贴底抓球改 0~3。

## 1. 目标与范围

实现 Task.md 序列中的「捡球」阶段 **PickBall**：与 `t_search_ball`（SearchBallAll，下视见球提前退出）衔接，
对下视画面里的球做**平移对准闭环** → 定时前冲把爪送到球位 → **坐底**（离底 5cm 目标持续下压）保持 1s → **上浮定深回 60cm 离底**。

- 序列（用户 2026-10-07 口径）：**对准（连续 10 帧框中心在画面中心 10px 内）→ 前进 0.5s → 坐底 1s → 上浮定深 60cm**。
- 全程使用**图像卡尔曼 + PID 闭环**（对准段）；前冲/坐底/上浮为既有原语，不加视觉。
- 「不是球在正中心时捡」：爪与下视相机不同轴，**对准把球送到画面中心，前冲 0.5s 把爪平移到球上**——爪偏置隐含在前冲时长里（隐式补偿，上车标定）。
- 守 Task.md §5 红线：全程防露头定深、绝不发 depth=0、每段有出口（对准超时兜底；dive 段沿用全局无兜底口径）。

## 3. PickBallAll 状态机（一个 Stage，内部 5 子步骤）

```
enter: idx=0；sts=[{}×5]；align 子步骤建 _PickKF2、计数器、计时器
       若 getattr(ctx,'ball_lost',False) → 直接 return None 秒退（撞球搜索已失败，无球可捡）

[0 ALIGN 对准]（自定义段，非 t_function 原语）
   每拍：poll('bottom','ball')
     ├ 新帧 → KF.update(cx,cy)；计数器：|dx_kf|≤10 且 |dy_kf|≤10 → +1，否则清零
     │        计数 ≥ AUV_PICK_ALIGN_N(10) → 对准完成 → idx=1
     │        控制律(§5)：sway=PID(dx_kf,vcx_kf)，surge=PID(dy_kf,vcy_kf)（死区/限幅/trust 门控）
     ├ 无新帧 → KF.predict(dt)：coast≤0.5s 用预测值继续闭环；超窗 → 推力归零（冻结）
     └ KF 丢失 ≥2s → 推力归零，原地定深锁航向等待（直到总超时）
   超时 AUV_PICK_ALIGN_TIMEOUT_S(20s) → ctx.pick_lost=True（say 警告）→ idx=4（跳上浮收尾）
   每拍 depth=_depth_out(st, AUV_PICK_HEIGHT_CM=60)、yaw=_yaw_hold

[1 FWD 前冲]    forward_step(sts[1], duration_s=0.5, target_height_cm=60)   定时+锁当前航向
[2 SIT 坐底下潜] dive_step(sts[2], target_height_cm=5)                        融合深度入带(±8cm)完成，无兜底
[3 HOLD 坐底保持] hover_step(sts[3], duration_s=1.0, target_height_cm=5)      固件深度环持续下压；未来合爪挂这里
[4 ASC 上浮]    dive_step(sts[4], target_height_cm=60)                       回 60cm 离底 → return None 阶段完成
```

- 子步骤模式与 t_task4/t_return 完全同构：`while idx<5`，子步骤返回 None → idx+1，全部完成 → 阶段 None。
- ALIGN 段推力每拍经 `max(-1,min(1,·))` 后进 `_cmd`；sway 输出乘 `AUV_SWAY_SIGN × AUV_PICK_SWAY_SIGN`。
- `ctx.pick_lost`：下游需要球的 Stage 在 `enter` 检查即秒退（§0.4-7），不改 mission.py。

## 4. 图像卡尔曼（_PickKF2 = x/y 两路独立 1D CV）

设计**整体继承撞球方案 §4 已定稿的 _BallKF**（含 v2.2 viskf 真机教训），差异只有两点：双轴、无 w 通道（对准不用框宽）。

- **模型**：单轴一维常速 CV，状态 `[c, vc]`（像素、像素/s），F=[[1,dt],[0,1]]，量测 z=c。x 轴、y 轴各跑一套同参实例，无耦合项（决策 2）。
- **量测噪声**：`AUV_PICK_KF_R_PX2 = 15²`（检测框中心抖动 ~15px，TODO 实测回填）。
- **过程噪声**：`AUV_PICK_KF_Q_ACC = 800`（偏大=信观测；对准时机体在动、球静止，像的移动近似匀速）。
- **新息门限**：`|z − c_pred| > 3σ + floor(√R)` → 该轴拒收按丢帧处理；单轴连续拒收 5 帧 → 该轴 KF 重置重捕（v2.2 教训：不加 floor 好观测被误拒）。
- **贴边防护**：该帧 clip 标志置位 → 本帧量测方差 ×4。
- **trust 门禁**（v2.2 最大的坑）：仅当"最近有效观测 age ≤ 0.2s 且两轴 σ ≤ 45px(3√R)"才允许输出进 PID；否则推力归零。**绝不拿长时间外推值控推力**。
- **丢失三级节拍**（对齐撞球/v2.2：coast 0.5 / trust age 0.2 / lost 2.0）：
  1. 丢帧 ≤ 0.5s：纯预测滑行，用预测 (dx,dy) 继续闭环（短遮挡不脱靶）；
  2. coast 超窗：< 2s 推力归零冻结，保位等待重捕；
  3. ≥ 2s：同冻结（等待至对准总超时兜底，§0.4-6）。
- **首帧初始化**：KF 未初始化时推力为 0，首个有效观测直接置状态（c=z, vc=0）。
- 与撞球复用关系：若将来 `t_hit_ball.py` 的 _BallKF 已落地，_PickKF 可 import 后双实例组合；落地前本文件自包含实现（约 50 行）。

## 5. 对准 PID（双通道推力直出）

与撞球 PID 的本质区别：撞球闭 yaw（PID 输出**递推目标角**，固件有 yaw 内环）；本阶段 sway/surge 是**开环推力通道**，PID 输出**就是推力**（同过门方案 sway 副回路形态）。

```
raw_sway  = Kp_s·dx_kf + Kd_s·vcx_kf      # 正 = 需要右移（dx>0 球在画面右侧 → 右移追）
raw_surge = Kp_g·dy_kf + Kd_g·vcy_kf      # 正 = 需要前进（方向符号上车标定，见下）
死区：|dx_kf| ≤ AUV_PICK_DEAD_PX(8)  → raw_sway=0；|dy_kf| ≤ 8 → raw_surge=0
限幅：clip(±AUV_PICK_THRUST_MAX=0.35)
符号：sway_cmd  = raw_sway  × AUV_PICK_SWAY_SIGN × AUV_SWAY_SIGN
      surge_cmd = raw_surge × AUV_PICK_SURGE_SIGN
```

- **死区 8px 必须 < 判据窗 10px**：进死区推力归零 → 车稳住 → 滤波偏差停在 ±8 内 → 计数器能连续攒满 10 帧（若死区 ≥ 窗，计数永远凑不满——落地时别改大）。
- **D 项默认关**（Kd=0）：KF 已平滑，先 P 起步；震荡再加 D（用 KF 速度，不差分——过门方案约定）。
- **符号标定（上车首测项）**：
  - sway：`AUV_SWAY_SIGN=1` 约定正推力=右移；球在画面右（dx>0）时要右移 → 理论上 `AUV_PICK_SWAY_SIGN=+1`，实测反了改 −1。
  - surge：下视图像 y 方向与机体前后对应关系取决于相机安装朝向，**纸面定不了**：若图像上方=机体前方，前出让球像下移，则 dy>0（球在下方）要**后退** → SURGE_SIGN=−1；安装反装则 +1。上车一次实测。
  - 若实装发现横/纵轴互换（相机转了 90° 安装）：把两路 PID 的输入对调即可（一行），不改结构。
- **参数初值**：Kp=0.002 推力/px（150px 满偏差 → 0.30 推力，与限幅 0.35 匹配），Kd=0，Ki=0（开环推力通道不带积分，防丢帧期积分漂移）。

## 8. 已知风险

| 风险 | 缓解 |
|---|---|
| 下视相机 60cm 高度视场罩不住球（球迟迟不入画） | 搜索段本就以"下视见球"退出，交接时球刚入画；对准 PID 从画面边缘往中心拉（限幅 0.35 足够）；始终不入画 → 20s 超时兜底 |

| surge/sway 符号或轴序与假设不符 | §5 三个一行开关（SWAY_SIGN / SURGE_SIGN / 输入对调），上车首测逐个确认 |
