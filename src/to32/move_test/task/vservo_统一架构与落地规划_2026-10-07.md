## 1. 架构总览：一个公共层，三个薄任务

```
task/vservo.py（公共层，~140 行，零 task_config 依赖、零全局默认参数）
  ├ KF1D            1D 常速卡尔曼（构造注入 R/Q/门限/coast/trust，撞=1个、捡=2个、门=1个）
  ├ KF2D            两个 KF1D 组合（捡球 cx,cy 专用糖）
  ├ PID             通用 PID（构造注入 kp/ki/kd/限幅，无任何全局键）
  ├ yaw_servo_step  前视族共用「误差→角速度→递推目标角」一步（撞/门同一语义的代码化）
  └ trust_ok / 命中计数器 / 丢失三级节拍（coast 0.5 → 冻结 → lost 处置）工具函数

盲段不新增原语（用户拍板 09:23）：统一复用 t_function 既有 forward_step（锁航向定深前进，
surge 显式可调）/ hover_step（锁航向定深零推力），映射见 §2。

task/t_hit_ball.py   撞球：ServoStage(yaw 环) + ram=forward_step（surge 显式）   （~120 行）
task/t_pick_ball.py  捡球：平移环（推力直出）+ 前冲/坐底=forward_step/hover_step（~150 行）
task/t_pass_gate.py  穿门：ServoStage(yaw 环) + 定深对门高 + 近距 sway + 穿越=forward_step（~180 行）
```

原则：**公共层只给零件，不给参数**；每个任务文件在 `enter()` 里用**自己的** `AUV_<任务>_*` 键构造自己的 KF/PID 实例——这就是"PID 参数独立"的落地方式（KF 参数同理独立，随每任务键空间走）。所有状态对象在 `enter()` 重建，测试模式循环重跑天然安全。

## 2. 盲段统一 = 既有原语，不新增（v1.1 用户拍板）

不新增任何盲冲原语。四个"盲段"全部映射到 t_function 既有 forward_step / hover_step
（语义统一：定时 + 锁航向 + 定深，参数各归各任务键）：

| 任务 | 盲段 | 既有原语实例 |
|---|---|---|
| 撞球 | ram 冲撞 | `forward_step(duration_s=AUV_HIT_RAM_S, surge=AUV_HIT_RAM_SURGE, target_height_cm=AUV_HIT_HEIGHT_CM, stage='Ram')` |
| 穿门 | 穿越门框 | `forward_step(duration_s=AUV_GATE_CROSS_S, surge=AUV_GATE_CROSS_SURGE, target_height_cm=AUV_GATE_DEPTH_CM, stage='Cross')` |
| 捡球 | 前冲补偿爪偏置 | `forward_step(duration_s=AUV_PICK_FWD_S, target_height_cm=AUV_PICK_HEIGHT_CM)`（surge 缺省巡航档） |
| 捡球 | 坐底持续下压 | `hover_step(duration_s=AUV_PICK_SIT_HOLD_S, target_height_cm=AUV_PICK_SIT_HEIGHT_CM)`（零推力，固件深度环下压） |

forward_step 本就支持显式 surge（None=默认巡航档），四种场景零改动覆盖；捡球方案 v1 的原设计
（前冲=forward_step、坐底保持=hover_step）就此成为全工程盲段统一口径，vservo.py 不含任何运动原语。
