## 2. 未完成清单（按"离能下水还差什么"排序）

### U1 ⛔ 实体 STM32 联调 —— 唯一的硬件级缺口（最高优先级）

* **现状**：本程序的下位机链路只在三种"假下位机"上验证过：① `--stm32 sim` 空跑（不开串口，只打印帧）；② 自测里合成的 48B 回帧；③ pty 假下位机 `[文档]`。
* **证据**：`mid.log` / `mid.out`（2026-09-11 17:00）首行即 `[STM32] 空跑模式(sim)：不打开串口` `[实测]`。板上没有第三份日志能证明真实串口跑通过。
* **注意**：`link_stm32.py:196-198` 在打开失败时会**静默降级为空跑**并只打一行日志——所以"程序跑起来了"不等于"下位机通了"，**必须看 `[ANCHOR]` 与遥测计数**。
* **完成判据**（三条同时成立）：日志出现 `[ANCHOR] 首帧遥测`；`遥测 N 帧` 以 10Hz 稳定增长；`下位机 TX` 里 `0x0C` 计数 ≈ 遥测帧数（1:1）。
* **建议命令**：`python3 main.py --log /userdata/GrandRDK/docs/real.log`（不带 `--stm32 sim`）。

### U2 ⛔ 真实上位机 UI 直连板端 —— 未证实（2026-09-15 已加"首个下行帧源 IP"日志，见 §10）

* **现状**：上位机 UI 的报文语义已被逐条实测（`上位机通讯协议.md`，劫持 `target_ip=127.0.0.1` 采集，**报文没到板上**）`[实测-于PC侧]`；板端收到的 `$CMD` 来自真实 UDP 8080（`mid.out`）`[实测]`，但**本程序日志不记录对端 IP**（`link_pc.py` 只在启动时打一行监听地址，`mode_dispatcher.report()` 也只打计数），因此无法自证对端就是那台 PC。
* **缺口**：缺一次"真机 UI → 网线 → 板端 8080"的可追溯记录。
* **建议（1 行改动即可自助）**：在 `link_pc.py` 首次收到 `$CMD` 时打印源地址（`PcLink.pc_addr` 已经有值，仅未输出）；或旁路用板上 `/userdata/cmd_watch.py` 被动监听 8080 看上位机每帧。

### U3 ⛔ AUV 自主逻辑是空壳（只有一个壳）

* `mode_auv.py:61` `tick()` 体是 `pass`，任务状态机注释仍写着 `# 后续在这里写任务/路径/闭环节点`。
* `mode_auv.py:71` `build_telemetry()` 直接 `return None  # TODO`——所以 AUV 期间 `$TEL` 是靠 `mode_dispatcher._send_tel()` 回落到 `tel_builder` 统一映射才有的（**不会断流**，但也没有任务态信息）。
* `mode_auv.py:27` 状态机 `idle/init/run/hold/abort` 只是注释与一个恒为 `"idle"` 的字符串。
* **AUV 目前实际行为**：进模式 → 下发 `0x04 0x02` 预编程 → **不下发任何 `0x09`** → 忽略手柄杆位（仅计数）→ 不发自有 `$TEL`。**没有任何自主控制**。
* **完成判据**：`tick()` 内有闭环/任务推进，且 `on_downlink()` 用遥测做深度/航向闭环（钩子已就绪）。

### U4 🟠 ROV 的 heave / yaw 是"降级语义"

* 固件 `0x09` 只有 `[8] surge` / `[9] sway` 两个推力字节，**没有 heave/yaw 推力槽位**，11B 已排满。
* 现实现：`heave` 积分成目标深度、`yaw` 积分成目标航向（`mode_rov.py:60-66`），参数写死在实例属性里（`mode_rov.py:32-35`：`yaw_rate=60°/s`、`depth_rate=20cm/s`、`heave_sign=+1`、`yaw_mirror=True`）。
* 这是**已定的降级方案**，但"四个轴都是推力"的上位机设计意图与固件能力存在语义差。需甲方确认接受（见 `ROV_指令与V2协议对应关系.md` §9-1）。

### U5 🟡 文本 `$PID` 仍全量丢弃（决策 D 维持）；**二进制 PID 中继 v3.8 已打通（2026-10-07）**

* `mode_rov.py:87-88`：`$PID` 只打一行日志后丢弃。上位机 UI 为 ch `0~11`，而固件 `0x01` 只认 ch `0~3`（Pitch/Yaw/Roll/Depth），且 STANDBY 下整帧忽略。（2026-09-15 决策 D：文本路径暂不打通，维持）
* `link_stm32.frame_set_pid()` 已写好（组帧正确），但 2026-09-13 grep 确认 **0 处调用**。
* **2026-10-07 更新（v3.8）**：上位机 PID 面板改发 **11B 二进制帧**（`CD 0A 01 CH KP_LE KI_LE KD_LE DC`，增益×100 / int16 小端 / ±327.68）——中位机 `protocol.parse_binary_pid` 严格校验（帧长/头/功能码/通道上限/帧尾）后**原字节转发** STM32，`frame_set_pid` 的 `0x01` 组帧路径由 `mode_dispatcher._on_pid_binary` 接管，**不再是"无调用方"**。默认仅放行 CH 0~3（`PID_BINARY_MAX_CH=3`，4~7 为参考固件补偿环、**未实机核实**）；中继独立于模式切换、不解除急停、不保存。另新增 `$TASKPID,<req>,gate,P,I,D#`（仅 S100 处理，更新过门 `GatePid` 并 ACK 回 8081；不启动任务/不切模式；撞球/捡球未实现明确拒绝）。
* **完成判据**：文本路径维持决策 D；二进制路径 ch 0~3 校验转发已落地——补丁包 `源码\GrandRdk-2.5\tests\test_pid_relay.py`（16 项）+ `test_task_pid.py`（14 项）无硬件回归全过 `[自测]`（脚本未拷入项目/未入 git，从补丁包目录直接可跑）；**STM32 实体接受/保存未验证**（仍属 U1 范畴）。

### U11 🟡 软急停语义缺口（安全相关，需决策）（2026-09-15 决策 B：两端补显式 `$ESTOP#`，见 §10）

* 上位机的"急停" = **全零 `$CMD`**，与"摇杆回中"报文完全同形。只要它以 20Hz 持续到达，deadman **不会触发**，中位机只能做到"零推力"，**进不了 STANDBY**。
* `protocol.py:86` 的 `is_zero_cmd()` 判断函数**已写好但全项目 0 处调用**（本次 grep 确认）。
* 三个候选方案（A 连续 N 帧全零判急停 / B 约定用扩展帧 `$ESTOP#` / C 维持现状）见 `ROV_指令与V2协议对应关系.md` §4，**尚未决策**。

### U12 🟡 急停"解除"手段与真实 UI 不匹配（2026-09-15 已补 UI「解除急停」按钮，见 §10）

默认 `ESTOP_LATCH=True`，解除需发 `$ESTOP,0#`——但**上位机 v3.2.3 UI 不发这个帧**（`上位机通讯协议.md` §6.1 明确"v3.2 UI 不发这两个帧"）。
→ 现场一旦触发锁存，用真实 UI **无法自行解除**，只能靠 `--estop-no-latch`（收到新 `$CMD` 即解除）或人工发帧。**需在 UI 侧补按钮或改默认策略。**

### U13 🟡 无线 / LoRa 链路不支持

无线模式下上位机指令走 PC 地面 LoRa 串口（9600，5Hz），**不经 UDP 8080**（`上位机通讯协议.md` §1）。本程序只监听 UDP → 无线模式下收不到 `$CMD` → 1.0s 后 deadman 急停锁存。**无线联调未做**（且无线不传图像）。

### U14 🟡 视频只有一路实体相机

cam2 依赖 cam2 节点（板上现为元数据节点）。双相机实体接入未验证；与 `vp5.1`（带 YOLO 的重链路）**互斥**，两者不能同时跑。

### U15 🟡 一批 V2 组帧函数**写好了但没人调用**（2026-09-15 勘误：0x02/0x03/0x05/0x08 的组帧函数**根本不存在**，全项目只有 0x01/0x0A 两个）

→ 即 V2 的 `0x01/0x02/0x03/0x05/0x08/0x0A` 这 6 个功能码**当前一个都没打通**（`0x04`/`0x09`/`0x0C` 已用）。

### U16 🟡 模式记忆只在测试路径验证过

`mode_state.json` 在生产路径**不存在** `[实测]`。自测用的是 `/tmp/selftest_mode_state.json`（隔离设计，正确），但意味着"上位机切换 → 落盘 → 重启沿用"这条链路在生产路径上**没有真实运行记录**。

## 4. 接口契约速查（三端各说什么话）

### 4.1 上位机 → 中位机（UDP 8080，文本帧，`\r\n` 结尾）

| 帧 | 格式 | 语义要点 |
|---|---|---|
| `$CMD` | `$CMD,surge,sway,heave,yaw,led1,led2,mode,grab,store#` | 唯一"运动+状态"载体，**没有独立的状态帧**；有线 20Hz / 无线 5Hz；`mode: 0=ROV 1=AUV`；`grab:0/1/2`、`store:0/1`、`led∈[0,100]` |
| `$PID` | `$PID,ch,p,i,d#` | 点"应用并下发"时逐通道各一帧；**文本路径维持丢弃（决策 D，见 U5）**；v3.8 起请走下方二进制 PID |
| **11B 二进制 PID** | `CD 0A 01 CH KP_LE KI_LE KD_LE DC` | **v3.8**：增益×100 / int16LE / ±327.68；中位机校验后**原字节转发** STM32；默认仅 CH 0~3（`PID_BINARY_MAX_CH=3`）；不切模式/不解急停/不保存（见 U5） |
| `$TASKPID` | `$TASKPID,<req>,gate,P,I,D#` | **v3.8**：命名任务参数，**仅 S100 处理、不下发 STM32**；gate 更新过门 `GatePid` 并 ACK 回 8081；撞球/捡球未实现明确拒绝；不启动任务/不切模式 |
| `$VID` | `$VID,1#` / `$VID,0#` | 板端拦截，**不下发**下位机；真正开关 `:5000` 推流 |
| `PING` | `PING`（发到 8081） | 必须回 `PONG` 到**源端口**，否则 UI 时延恒 `--` |
| `$ESTOP#` / `$ESTOP,0#` | 扩展兜底 | **v3.2 UI 不发**（U12） |

### 4.2 中位机 → 上位机（UDP 8081，`$TEL,<41 字段>#`）

41 个索引由上位机**硬编码**，缺字段必须补 0（不可省略，否则整帧错位）。

| 索引 | 含义 | 来源 | 现状 |
|---|---|---|---|
| 0/1/2 | roll / pitch / yaw（实际） | V2 ÷100 | ✅ |
| 3/4/5 | gx / gy / gz | V2 角速度 ÷100 | ✅ 方向约定待核对（U10） |
| 6 | 深度(m) | 实际深度 ÷10000 | ✅ |
| 7-9 | vx/vy/vz | —— | ⬜ 恒 0（U9） |
| 10/11/12 | 目标 roll/pitch/yaw | V2 ÷100 | ✅ |
| 13-15 | 目标角速度 | —— | ⬜ 恒 0 |
| 16 | 目标深度(m) | V2 ÷10000 | ✅ |
| 17-19 | 目标线速度 | —— | ⬜ 恒 0 |
| 20-24 | 电池/舱温等 | —— | ⬜ 恒 0 |
| 25-32 | thr0~thr7 | V2 电机原值 ÷`MOTOR_SCALE`(1000) | ✅ |
| 33-36 | thr8~thr11 | —— | ⬜ 恒 0（V2 仅 8 路） |
| 37/38/39 | ax / ay / az | V2 ÷100 | ✅ |
| 40 | alt | 高度计 UDP 8082 | ⬜ 恒 0，不归本程序 |

### 4.3 中位机 ↔ 下位机（串口 V2：`CD LEN FUNC DATA DC`，`LEN = DATA+3`，≤64B，无 CRC）

| FUNC | 名称 | 中位机是否在用 |
|---|---|---|
| `0x04` | 模式命令（`0x00`启动/`0x01`急停/`0x02`预编程/`0x03`ROV/`0x04`测试） | ✅ 已用 |
| `0x09` | 摇杆综合运动（11B：目标P/Y/R ×100 + 目标深度 u16×100cm + surge/sway int8 + FLAG） | ✅ 已用（**收到即切 ROV，无 STANDBY 守卫**） |
| `0x0C` | 遥测请求/回帧（**唯一回帧帧，1:1**，回 48B：`CD 2F 0C <44B> DC`） | ✅ 已用（10Hz） |
| `0x01` `0x02` `0x03` `0x05` `0x08` `0x0A` | 设置PID / 测试推力 / 目标姿态 / 保存 / 读姿态 / 目标深度 | 🟡 `0x01` **2026-10-07 起由二进制 PID 中继调用**（`_on_pid_binary` 转发，见 U5）；`0x02/0x03/0x05/0x08/0x0A` 仍无调用方（U15） |

**遥测 48B 布局**：`0..5` 目标 P/Y/R（int16×100）· `6..11` 实际 P/Y/R · `12..17` 角速度 · `18..23` 加速度 · `24..39` 电机 0~7 原值 · `40..41` 目标深度（u16, cm×100）· `42..43` 实际深度（u16, cm×100，**负值被固件强制 0**）。
**量纲坑**：角度 int16 度×100；深度 u16 **cm×100**（`上位机对接说明_V2.md` §6 的"1.00 m"示例是错的，实为 1.00 cm）；推力 int8 固件再 ×2；**上电约 8s 初始化完成**，上电即发帧可能丢。

### 4.4 视频（TCP 5000）

`http://<板端IP>:5000/cam1`（`/cam2` 占位）——与 `vp5.1` 的 `mjpeg_bridge` 同一约定，上位机不改代码。`$VID` 开关；**与 vp5.1 互斥**（都独占摄像头设备节点）。

## 7. 安全红线（改代码前必读）

1. **`0x09` 没有 STANDBY 守卫**：急停后再发一帧 `0x09`，固件会**静默退出急停**。所以锁存期间必须抑制 `0x09`（现实现：`mode_rov.on_cmd` 锁存时直接 `return`）。
2. **AUV 期间不得下发 `0x09`**（固件收到即自动切回 ROV）。
3. **冷启动锚定**：首帧遥测到达前不跑模式 tick；到达后目标量锚定到实测值，避免一上电"回水面/转向 0°"。
4. **急停判定只看帧间隔，不看内容**（全零 `$CMD` 与摇杆回中同形）——相关缺口 U11。
5. **串口打开失败会静默转 sim**（`link_stm32.py:196-198`）：排障时永远先确认是不是 sim。
6. **上电 8s 内不发帧**（固件初始化未完成）。
