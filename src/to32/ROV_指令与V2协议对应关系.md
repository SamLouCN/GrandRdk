## 1. 总览：一条指令怎么落地

| # | 上位机下行（UDP 8080） | 中位机行为（ROV 模式） | 下位机 V2 帧（串口） | 下位机效果 |
|---|---|---|---|---|
| 1 | `$CMD.mode=0`（遥控模式按钮 / 循环帧携带） | 模式切换：`RovMode.on_enter()` | `CD 04 04 03 DC`（0x04=模式，DATA=0x03 ROV） | 直接置 `CON_MODE_ROV` |
| 2 | `$CMD.surge/sway`（∈[-1,1]，20Hz） | 透传，量化 int8 | `0x09` DATA[8]/[9] | 前后/左右推力（固件再 ×2 → ±254） |
| 3 | `$CMD.heave`（∈[-1,1]） | **积分成目标深度**（20 cm/s 满偏） | `0x09` DATA[6..7]（uint16, cm×100） | `Target_Depth`，深度环闭环 |
| 4 | `$CMD.yaw`（∈[-1,1]） | **积分成目标航向**（60°/s 满偏）+ 取负抵消镜像 | `0x09` DATA[2..3]（int16, 度×100） | `Target_Yaw_Angle`，航向环闭环 |
| 5 | （上位机不提供姿态角） | 固定 0 | `0x09` DATA[0..1]/[4..5] | 目标 Pitch/Roll = 0（保持水平） |
| 6 | `$PID,ch,p,i,d` | ⚠️ **全丢弃**（2026-09-15 决策 D：暂不打通；改为计数+首帧提示，`frame_set_pid` 已加越界钳位） | ——（未下发） | 无法在线调参（见 §5.3） |
| 7 | `$VID,1/0` | 板端拦截，仅记录 | —— | STM32 不认识该帧，正确做法就是不下发 |
| 8 | `$CMD.led1/led2`、`grab`、`store` | 仅计数丢弃 | ——（V2 无对应 FUNC） | 需固件扩展（见 §5.4） |
| 9 | 急停：**链路静默**（无 `$CMD` 到达）> 1.0s | deadman 触发 → 锁存 | `CD 04 04 01 DC` | 进 STANDBY + `MOTOR_STOP()` |
| 10 | 下位机遥测（上行） | 10Hz 发 `0x0C`，解析 48B → 组装 `$TEL` | `CD 03 0C DC` → `CD 2F 0C …(44B) DC` | 回传姿态/角速度/加速度/电机/深度 |

> 关键：**ROV 模式下中位机不做混控、不做姿态/深度环**，只做「摇杆量 → V2 帧」的翻译；控制律在下位机固件里。

> **2026-09-15 空闲静默（需求变更）**：中位机**只在 0x09 载荷变化时下发** —— 摇杆在中间且目标量未变时，F 口不再出现 20Hz 全零 `CD 0E 09 00…00 DC`；回中瞬间仍会补发一帧把 surge/sway 归零。开关 `config.MOTION_SILENT_WHEN_IDLE`（默认 True）。固件侧 `Motion_Flag/Motion_Time` **只写不读**（`JXZK_XLB_Protocol.c:760/761/786`），故无欠帧看门狗，静默安全。

## 2. 核心帧 `0x09`（摇杆综合运动）逐字节对照

整帧 15 B：`CD 0E 09 <11B DATA> DC`（`LEN = 0x0E = 11 + 3`）

| DATA 偏移 | 字段 | 类型 / 换算 | 固件目标变量与处理 | 中位机 RO​V 模式填什么 | 来自上位机 |
|---|---|---|---|---|---|
| `[0..1]` | 目标 Pitch | int16LE，度 ×100 | `Target_Pitch_Angle`，归一化 **±90°** | 固定 `0` | ——（上位机不下发姿态） |
| `[2..3]` | 目标 Yaw | int16LE，度 ×100 | `Target_Yaw_Angle = −归一化(v, ±180°)`（**固件取负/镜像**） | `−target_yaw_deg`（内部目标取负，抵消镜像） | `$CMD.yaw` 积分 |
| `[4..5]` | 目标 Roll | int16LE，度 ×100 | `Target_Roll_Angle`，归一化 **±90°** | 固定 `0` | —— |
| `[6..7]` | 目标深度 | **uint16LE**，cm ×100 | `Target_Depth`（单位 **cm**），**仅钳上限 200** | `target_depth_cm`（0~200，钳位） | `$CMD.heave` 积分 |
| `[8]` | surge 前后分量 | **int8**（固件 **×2**） | `Forward_Thrust`（实际域 ±254） | `round(surge × 127)` | `$CMD.surge` ∈[-1,1] |
| `[9]` | sway 左右分量 | **int8**（固件 ×2） | `Sidesway_Thrust` | `round(sway × 127)` | `$CMD.sway` ∈[-1,1] |
| `[10]` | FLAG | uint8 位域 | bit0 `FUNC2_STICK_STOP`：**仅停 surge/sway，保留姿态角与深度** | `0x00`（当前恒 0，未使用） | —— |

**副作用（两处，ROV 语义强相关）**
1. **收到 `0x09` 即自动切 ROV**：固件若当前非 ROV，先存 `Last_Con_Mode`，再强制 `Con_Mode = CON_MODE_ROV`；
2. 置 `Motion_Flag = 1`、`Motion_Time = HAL_GetTick()`（固件侧的"手柄在位"标记）。

**🚨 安全红线**：`0x09` 的处理函数**没有 STANDBY 守卫**（对比 `0x01`/`0x03`/`0x0A` 都有 `if (Con_Mode == STANDBY) return;`）。因此**急停后只要再发一帧 `0x09`，固件会静默退出急停并进入 ROV**。
→ 中位机必须自己锁存急停态，解除前抑制一切 `0x09`（`mode_rov.on_cmd` 在 `ctx.estop_latch` 时直接 return；`mode_dispatcher._check_deadman` 负责锁存）。

### 2.1 字节级示例（按当前实现参数计算，非实测）

条件：上位机持续发 `$CMD`，`surge=0.50`、`sway=−0.30`，`heave/yaw` 积分后内部目标 = 深度 50.00 cm、航向 +30.00°：

```
CD 0E 09 00 00 48 F4 00 00 88 13 40 DA 00 DC
│  │  │  └──┬──┘ └──┬──┘ └──┬──┘ │  │  │  │  └─ 帧尾 DC
│  │  │     │       │       │    │  │  │  └──── FLAG = 0x00
│  │  │     │       │       │    │  │  └─────── sway int8 = −38（−0.30×127）
│  │  │     │       │       │    │  └────────── surge int8 = +64（0.50×127）
│  │  │     │       │       │    └───────────── 目标深度 raw 5000 = 50.00 cm（uint16LE：88 13）
│  │  │     │       │       └────────────────── 目标 Roll = 0
│  │  │     │       └────────────────────────── 目标 Yaw raw −3000 = −30.00°（镜像后，LE：48 F4）
│  │  │     └────────────────────────────────── 目标 Pitch = 0
│  │  └──────────────────────────────────────── FUNC = 0x09（摇杆综合运动）
│  └─────────────────────────────────────────── LEN  = 0x0E = 11 + 3
└────────────────────────────────────────────── 帧头 CD
```

## 3. 模式命令 `0x04`（`$CMD.mode` 的落地）

帧：`CD 04 04 <code> DC`（5 B）

| code | 含义 | 中位机何时发 | 固件行为（V2 实现） |
|---|---|---|---|
| `0x00` | 启动/恢复 | 当前未使用 | **仅当当前为 STANDBY 才生效**；恢复 `Last_Con_Mode`（要求 ∈ `[TEST, ROV]`，否则落 ROV） |
| `0x01` | 急停 | deadman 超时（下行中断 > `ESTOP_TIMEOUT_S`） | 非 STANDBY 时先存 `Last_Con_Mode` → 置 STANDBY → `MOTOR_STOP()` |
| `0x02` | 预编程（AUV） | `$CMD.mode=1`（AUV，非本文范围） | 直接置 `CON_MODE_PREGRAM` |
| `0x03` | ROV | `$CMD.mode=0`；启动时初始模式 | 直接置 `CON_MODE_ROV` |
| `0x04` | 测试 | 当前未使用 | **先 `memset` 清零 8 路测试油门**，再置 TEST |

**⚠️ `0x04` 无 STANDBY 守卫**：急停后可直接被 `0x04 0x03` 拉回 ROV（"恢复"语义因此不对称）。
→ 实现中 `RovMode.on_enter()` 有 `if not ctx.estop_latch:` 守卫，锁存期间不下发模式帧。

**工程注意**：`$CMD.mode` 是**循环帧携带的状态位**（不是一次性事件），上位机点「遥控模式」时会立即补发一帧含 `mode=0` 的零杆位 `$CMD`。中位机按"值与当前不同才切换"处理，避免 20Hz 重复切模式。

## 4. 急停链路（ROV 模式最容易踩的坑）

上位机的"急停"语义 = **全零 `$CMD`**（与"摇杆回中"在报文上**完全同形**，无法区分）。因此：

| 场景 | 上位机实际发的报文 | 中位机行为 | 下位机 |
|---|---|---|---|
| 上位机按急停 / 手柄断开 | 全零 `$CMD`（`build_emergency_stop()`） | 若该帧**持续到达**：仅表现为 0x09 里 surge/sway=0、目标角/深度不变 → **零推力但不进 STANDBY** | 推进器停推，姿态环/深度环继续守当前目标 |
| 链路中断 / 上位机停止发送 | 无报文 | `ESTOP_TIMEOUT_S`（默认 1.0s）超时 → 发 `0x04 0x01` 并**锁存** | 进 STANDBY + `MOTOR_STOP()` |
| 锁存期间又来 `$CMD` | 任意 | `ESTOP_LATCH=True`（默认）→ 保持锁存、抑制 `0x09`；发 `$ESTOP,0#` 或加 `--estop-no-latch` 才解除 | 保持 STANDBY |
| 上位机切链路（有线→无线） | ① 全零 `$CMD` → ② `$VID,0#` | ① 零推力；② 停推流（板端拦截） | 同"急停"行 |

**⚠️ 已知缺口（需甲方决策）**：只要上位机持续以 20Hz 发送全零 `$CMD`，中位机的 deadman **不会触发**，因此"软急停"只能做到零推力，做不到进 STANDBY。
可选处理（择一，需改代码）：
- 方案 A：中位机对"连续 N 帧全零 + 无摇杆输入"判定为急停（`protocol.py:is_zero_cmd()` 已备好判断函数，当前未用）——风险：真·摇杆回中也满足，会误急停；
- 方案 B：约定上位机急停用扩展帧 `$ESTOP#`（中位机已支持：`mode_dispatcher._on_raw`）+ `$ESTOP,0#` 解除；
- 方案 C：维持现状（零推力 + 依赖链路中断 deadman），仅在文档中明确语义。

## 5. 未下发 / 需固件配合的字段

### 5.1 `$VID`（视频开关）
板端拦截，**不下发**给 STM32（V2 无对应 FUNC）。中位机 `on_vid()` 仅记录；视频推流由视觉模块（TCP 5000）负责。

### 5.2 运动相关硬约束：heave / yaw **没有推力槽位**
`0x09` 的 11 B 已排满：前 8 B 是**目标姿态角 + 目标深度（目标量）**，只有 `[8]`/`[9]` 是推力。
固件中**不存在 heave 推力槽位，也不存在 yaw 推力槽位**。因此上位机的 `heave/yaw` 只能按"目标量旋钮"解释（中位机做积分），这与"`$CMD` 四个轴都是推力"的设计意图存在语义差，属**已定降级方案**。

### 5.3 `$PID`（PID 调参）
| 项 | 上位机侧 | 固件侧（V2） |
|---|---|---|
| 通道数 | UI 为 ch `0~11`（12 路推进器语义） | 仅接受 ch **`0~3`** = `0`Pitch / `1`Yaw / `2`Roll / `3`Depth（`ch > 3` 整帧丢弃；`DATA 长度必须 = 7`） |
| 帧长 | `$PID,ch,p,i,d#` 文本帧 | `CD 0A 01 <ch> <Kp> <Ki> <Kd> DC`（11 B，int16LE ×100） |
| 生效条件 | 随时可点"应用并下发" | **STANDBY 模式下整帧忽略**（急停态无法调参） |

**当前实现：`$PID` 全部丢弃**（`mode_rov.on_pid` 仅打日志），因此上位机 PID 面板**当前不影响下位机**。
若要打通，需在 `mode_rov.on_pid` 里做映射：`ch ∈ 0~3` → 组 `0x01` 帧下发（注意 V2 通道序与 V1 不同：V1 是 1=Pitch/2=Roll/3=Yaw/4=Depth）。

### 5.4 `led1/led2`、`grab`、`store`
V2 **无对应 FUNC**，中位机仅计数丢弃（`mode_rov.dropped`）。如需支持，须在固件侧新增 FUNC（`0x0D/0x0E/0x0F` 保留未分配，可用于批量/扩展帧）。

### 5.5 `0x05` 保存参数（`$PID` 固化路径）
V2 分支为空实现，且底层 `Flash_SaveParameters()` 已被注释禁用 → **"保存到 Flash"当前完全不生效**，参数掉电即失。若需调参固化，必须先恢复固件侧调用。

## 6. 上行链：V2 遥测 48 B → 上位机 `$TEL` 41 字段

### 6.1 节拍
| 环节 | 节拍 | 说明 |
|---|---|---|
| 中位机发 `0x0C` 请求 | **10 Hz**（`POLL_HZ`） | `CD 03 0C DC` |
| 下位机回 `0x0C` 遥测 | **1:1**（每请求回一帧，10 Hz） | 固件 `PROTO_DEBUG_WIRELESS` **被注释** = 有线模式 1 请求回 1 帧；**不是 5:1** |
| 中位机发 `$TEL` | **10 Hz**（`TEL_HZ`） | 40 字段 + 帧尾 |
| `PING` → `PONG` | 事件驱动 | 回 `PING` 的**源端口**，否则 UI 时延恒为 `--` |

### 6.2 遥测回帧布局（48 B：`CD 2F 0C <44B DATA> DC`）
| DATA 偏移 | 字段 | 类型 / 换算 |
|---|---|---|
| `0..1` / `2..3` / `4..5` | 目标 Pitch / Yaw / Roll | int16LE，度 ×100 |
| `6..7` / `8..9` / `10..11` | 实际 Pitch / Yaw / Roll | int16LE，度 ×100 |
| `12..17` | 三轴角速度(P/Y/R) | int16LE，×100 |
| `18..23` | 三轴加速度(X/Y/Z) | int16LE，×100 |
| `24..39` | 电机 0~7 目标转速 | int16LE **原值**（8 路） |
| `40..41` | 目标深度 | **uint16LE**，cm ×100 |
| `42..43` | 实际深度 | **uint16LE**，cm ×100（**负值被固件强制为 0**） |

### 6.3 `$TEL` 41 字段索引对照（`tel_builder.tel_values`）
| 上位机索引 | 字段 | 来源 | 换算 |
|---|---|---|---|
| 0 / 1 / 2 | roll / pitch / yaw | 实际 `10..11` / `6..7` / `8..9` | ÷100 |
| 3 / 4 / 5 | gx / gy / gz | 角速度 `16..17`(Roll) / `12..13`(Pitch) / `14..15`(Yaw) | ÷100（**方向约定待实船核对**） |
| 6 | depth(m) | 实际深度 `42..43` | ÷100(cm) → ÷100(m) |
| 7..9 | vx / vy / vz | —— | 0（P5 光流接入 vx/vy） |
| 10 / 11 / 12 | t_roll / t_pitch / t_yaw | 目标 `4..5` / `0..1` / `2..3` | ÷100 |
| 13..15 | t_gx / t_gy / t_gz | —— | 0（V2 无目标角速度） |
| 16 | t_depth(m) | 目标深度 `40..41` | ÷100(cm) → ÷100(m) |
| 17..19 | t_vx / t_vy / t_vz | —— | 0 |
| 20..24 | 电池电压/电流/SOC/温度/舱温 | —— | 0（V2 无） |
| 25..32 | thr0..thr7 | 电机 `24..39` | ÷1000 → [-1,1]（`MOTOR_SCALE`） |
| 33..36 | thr8..thr11 | —— | 0（12 路预留，暂未装） |
| 37 / 38 / 39 | ax / ay / az | 加速度 `18..19` / `20..21` / `22..23` | ÷100 |
| 40 | alt | —— | 0（高度计走 UDP 8082 单独链路） |

> `$TEL` 字段数由上位机**硬编码为 41**，缺字段必须补 0 占位，不能省略，否则整帧错位。

### 6.4 冷启动锚定（避免一上电就"回水面/转向"）
首帧遥测到达前中位机**不下发 `0x09`**；到达后把内部目标量锚定到**实测值**：
`target_depth_cm ← depth_actual_cm`、`target_yaw_deg ← actual_yaw`（日志出现 `[ANCHOR]` 即链路已通）。

## 7. 单位与量纲速查（最易写错的地方）

| 项 | 规则 | 坑 |
|---|---|---|
| 角度 | int16LE，**度 ×100** | Pitch/Roll 固件归一 ±90°，Yaw 归一 ±180° **后取负** |
| 深度 | **uint16LE，cm ×100**（raw = cm×100） | ⚠️ `上位机对接说明_V2.md` §6 示例「目标深度 1.00 m = `CD 05 0A 64 00 DC`」**是错的** —— `0x0064 = 100`，即 **1.00 cm**；1.00 m 应为 `CD 05 0A 10 27 DC`（raw 10000）。钳位上限 200 cm = 2.00 m |
| 推力 | surge/sway **int8 原值**，固件 **×2** 后达 ±254 | 中位机侧 `×127` 量化；固件再乘 2 |
| 电机转速 | int16LE **原值**（不除 100） | `$TEL` 上报时 ÷`MOTOR_SCALE`(1000) 归一化 |
| PID 系数 | int16LE **×100** | 且 STANDBY 模式整体忽略 |
| 校验 | **无 CRC** | 仅靠 `CD`/`LEN`/`DC` 定界；`3 ≤ LEN ≤ 63`；失步需"锁 CD → 按 LEN 收满 → 校验 DC"重同步 |
| 上电 | 约 **8 s** 完成初始化 | 上电后立刻发帧可能丢，建议等待/重试 |
